🛠️ PostgreSQL RAG 테이블 생성 가이드

본 RAG 시스템을 정상적으로 구동하기 위해 PostgreSQL 데이터베이스에 아래의 2개 테이블과 인덱스를 반드시 생성해야 합니다.

💡 사전 준비사항: 벡터 검색(Embedding) 기능을 사용하기 위해서는 PostgreSQL에 vector 확장 기능(pgvector)이 활성화되어 있어야 합니다.
실행 전 명령창에서 CREATE EXTENSION IF NOT EXISTS vector;를 먼저 실행해 주세요.

1. 🧠 지식 청크 및 벡터 임베딩 저장소 (`tb_document_chunk`)

파인튜닝 및 RAG 검색에 활용되는 실제 벡터 데이터와 텍스트 조각들이 저장되는 테이블입니다.

CREATE TABLE public.tb_document_chunk (
	chunk_id serial4 NOT NULL,
	chunk_order int4 NOT NULL,
	reference_number varchar(255) NULL,
	"content" text NOT NULL,
	created_at timestamp DEFAULT CURRENT_TIMESTAMP NULL,
	embedding public.vector NULL,
	is_deleted int4 DEFAULT 0 NULL,
	model_id varchar(100) DEFAULT '3PL지식저장소'::character varying NOT NULL,
	CONSTRAINT tb_document_chunk_pkey PRIMARY KEY (chunk_id)
);
CREATE INDEX idx_chunk_model_deleted ON public.tb_document_chunk USING btree (model_id, is_deleted);
CREATE INDEX idx_document_chunk_is_deleted ON public.tb_document_chunk USING btree (is_deleted);
CREATE INDEX idx_document_chunk_ref_num ON public.tb_document_chunk USING btree (reference_number);

2. 📥 웹훅 스테이징 수신함 (`tb_raw_document`)

외부 시스템이나 웹훅을 통해 들어온 원본 텍스트가 'READY' 상태로 먼저 적재된 뒤 백그라운드 배치에 의해 임베딩 처리되는 테이블입니다.

CREATE TABLE public.tb_raw_document (
	raw_id serial4 NOT NULL,
	user_name varchar(100) NULL,
	"content" text NOT NULL,
	status varchar(20) DEFAULT 'READY'::character varying NOT NULL,
	created_at timestamptz DEFAULT now() NULL,
	processed_at timestamptz NULL,
	source_filename varchar(255) DEFAULT 'DIRECT_INPUT'::character varying NULL,
	model_id varchar(100) DEFAULT '3PL지식저장소'::character varying NOT NULL,
	CONSTRAINT tb_raw_document_pkey PRIMARY KEY (raw_id)
);
CREATE INDEX idx_raw_document_filename ON public.tb_raw_document USING btree (source_filename);
CREATE INDEX idx_raw_document_model_id ON public.tb_raw_document USING btree (model_id);
CREATE INDEX idx_raw_document_model_status ON public.tb_raw_document USING btree (model_id, status);
CREATE INDEX idx_raw_document_status ON public.tb_raw_document USING btree (status);
